\# ADR-0007 — Character State Machine



Status: Accepted



Date: 2026-07-16



\---



\# Context



As gameplay systems grow, maintaining independent boolean flags for player behavior becomes error-prone.



A centralized state machine provides a single source of truth for gameplay state.



\---



\# Decision



Project KATANA will use a dedicated StateMachine module.



All gameplay systems will query the StateMachine instead of maintaining their own gameplay state flags.



The first version supports only locomotion states.



Future gameplay states will be added incrementally.



\---



\# Consequences



Benefits:



\- Centralized gameplay logic.

\- Easier debugging.

\- Consistent gameplay rules.

\- Reduced coupling between systems.



Trade-offs:



\- Slightly higher architectural complexity.

\- Requires explicit state transition management.



\---



\# Future Work



Future versions may support:



\- Hierarchical states

\- Parallel states

\- State events

\- Animation integration

\- Network synchronization
